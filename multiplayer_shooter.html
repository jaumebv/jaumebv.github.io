Multiplayer Shooter — Cross-Engine UDP Networking

C# · C++ · Unity · Unreal Engine · Custom UDP Server · 2024/25

Overview

Multiplayer Shooter is a cross-engine networking project featuring a custom UDP server (C#) and two interchangeable clients built in Unity (C#) and Unreal Engine (C++). Both clients share the same lightweight protocol to synchronise movement, shooting, flags, pickups, scoring and match state in real time.

  • Server: Standalone C# (UDP sockets)
  • Clients: Unity (C#) & Unreal (C++)
  • Networking: Custom text-based packets over UDP
  • Core systems: Team assignment · Flag capture · Pickups · Respawn · Scoreboard
  • Year: 2024/25

Networking System (Server)

Authoritative UDP Server

The server manages connections, UIDs, team balancing, scores and game-wide broadcasts. On connect, the client receives a unique UID, team assignment and the current scoreboard. Disconnections are handled gracefully, removing transforms and team membership and notifying all clients.

  • Team and UID registries for fast look-ups and clean teardown.
  • Broadcast tick for transforms, scores and match events.
  • Packet router with dedicated handlers (shots, flags, pickups).

Unity & Unreal Clients

Shared Architecture

Both clients follow the same structure: NetworkManager and GameManager. The protocol is engine-agnostic, so features remain identical in Unity and Unreal.

  • Deterministic packet format and handlers on both engines.
  • Spawn/teardown mirrored across Unity and Unreal.
  • Coroutines/Timers for periodic sync and effects.

Shooting & Damage

A raycast determines aim direction; physical projectiles are spawned with lifetime control. On hit, damage is validated locally and relayed to the server. Friendly fire is disabled; when HP reaches zero, the player drops the flag (if any) and respawns.

Flag System

Two flags (one per team) support Picked, Lost, Returned, Captured states. The flag follows the carrier, returns when dropped, and can only be captured if the home flag is present.

Pickups

Health and Speed pickups derive from a shared base class. Only the local owner triggers pickup messages; the object hides and respawns after a delay.

Security & Exploit Mitigation

  • Position validation: speed/distance thresholds between frames.
  • UID ownership: bind UID to sender endpoint, reject mismatches.
  • Action validation: verify capture/flag preconditions.
  • Rate limiting & bans: throttle bursts, flag invalid packets.
