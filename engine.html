Overview

Mordibonx was built from the ground up in C++ and OpenGL to implement modern real-time rendering techniques and low-level engine architecture—without relying on an existing commercial engine.

Across more than seven months of development with Guillem Llorach, we designed an Entity Component System, a resource manager for async model loading, a multithreaded job system, dual forward and deferred lighting pipelines, shadow mapping across all light types and an interactive ImGui editor.

ARCHITECTURE

ECS, Resource Manager & Job System

Structured around an Entity Component System for clean data layout and modular behaviour, coordinated by an Engine hub that manages windowing, shader lifetimes and render modes.

  • Multithreaded job system: Offloads asset parsing and disk I/O onto worker threads so the render loop stays uninterrupted.
  • Live ImGui editor: Inspect entities, toggle rendering modes, tune post-processing shaders and profile lights in real time.
ECSJob SystemImGui
RENDER PIPELINE

Forward & Deferred Rendering with Shadows

Supports both forward per-object shading for simple scenes and a multi-pass deferred pipeline using a G-Buffer to decouple geometry from lighting cost.

  • Shadow mapping everywhere: Depth buffers for directional and spot lights, plus cubemap depth passes for omnidirectional point lights.
  • Multi-pass additive lighting: Accumulates light contributions across screen-space G-Buffer targets without per-mesh shader permutations.

POST-PROCESSING

GLSL Post-Process & Async Photo Mode

Framebuffer passes run selectable full-screen quad GLSL shaders—blur, pixelation, contrast, grayscale, inverse, CRT and cel/cartoon shading—switchable live from the editor.

  • Non-blocking Photo Mode: The CameraPhoto utility captures scene render targets and delegates disk encoding to the multithreaded job system.
  • Render-to-texture loop: Snapshots can even be bound back onto in-world surfaces in real time.
